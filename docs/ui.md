# UI guide: keep every screen looking like one product

The UI is plain JS and one stylesheet (`clipcrow/service/static/`). It was audited and redesigned page by page; new work must look like it
was always there. Read this before adding or changing anything a person sees.

## Rules
1. **Tokens only.** Colours, radii, spacing and shadows come from the variables at the top of `style.css` (`--surface`, `--line-strong`,
   `--accent`, `--r-sm`, ...). No literal colours in `app.js` or below the token blocks in `style.css`. A new look is a new token, defined for BOTH themes.
2. **Reuse the parts.** Page = `.card`s; field = `label.field` + control + `.hint`; yes/no option = `label.check`; action = `.btn` (`.primary` once per
   screen); status = `.chip`; empty and error states have their own classes. Look for an existing class before writing a new one.
3. **Every control is a field.** A text-like input (text, number, password, email, date, datetime-local, time, select, textarea) gets the field
   look automatically: `style.css` styles inputs by EXCLUSION, so a new input type is never left as the browser default. A control the browser
   draws itself (a file picker, a date picker's segments and icon, a range, a colour well, a scrollbar) must be themed in `style.css` too.
   The popup a browser opens (the calendar) is owned by the browser: it follows `color-scheme`, which we set per theme; do not try to restyle it,
   and do not swap in a third-party widget (the CSP forbids third-party requests and there is no build step).
4. **Both themes, small screens.** Dark is the default, light follows the system. Check a new screen in both and at 360 px wide (no horizontal scroll).
   Text keeps at least 4.5:1 against the surface under it. Keep a visible focus ring (`:focus-visible` is global; do not remove it).
5. **No job data in markup.** Build nodes with `el()` and set text with `textContent`; no `innerHTML`, no inline handlers, no inline styles (a test enforces it).
6. **Plain words.** Say what the thing does for the person, not how it works. Errors say what to do next. Marathi and Hindi copy stays Devanagari.
7. **Icons** are CSS masks (`.ico-*`), so there is no inline SVG markup and no `http://` in `app.js`.
8. **The logo** is the crow with scissors (`static/logo.png`, `logo-mark.png`, the favicons), made by `scripts/make_logo_assets.py` from `docs/assets/logo-source.webp`: never edit the PNGs by hand, change the source and run the script. Its bird and wordmark are DARK, so on this dark theme it always sits on a light tile (`--logo-tile`): `.brand-mark` in the header, `.auth-logo` on the sign-in cards. Do not place it straight on `--surface` or `--ground`.

## Adding a control: checklist
- Is there a class for it already? Use it. Otherwise add the CSS next to its relatives in `style.css`, with tokens, and a hover, focus and disabled state.
- Open it in dark and light (a Playwright screenshot is enough: `deviceScaleFactor: 2`) and compare it with the text field next to it: same height, border,
  radius, background, focus ring.
- New input type used in `app.js`? Add it to `STYLED_INPUT_TYPES` in `tests/test_ui_consistency.py` after you have checked it looks right. That test is
  there so a new kind of control cannot ship unstyled.

## Icons, logos and short copy (added 2026-11-17)
Research behind it: an icon without a word is guessed wrong far more often (icons with labels were predicted right 88% of the time, without 60%: NN/g and UserTesting), so **an icon sits beside its words and never replaces them**.
Helper text everyone needs stays visible; longer explanations go behind an "i" that opens on hover, focus or tap, stays open while the pointer is on it, and closes on Escape (WCAG 1.4.13). Nothing essential lives only there.
- **Icons** are `clipcrow/service/static/icons.css` (generated by `scripts/make_icons.py`, see `docs/icons.md`): Lucide line icons as `.i-<name>` and platform logos as `.i-plat-<slug>` (Simple Icons, CC0; the marks stay their owners' trademarks and only identify the platform).
  Use `icon('name', size)` in JS or `<span class="i i-name">` in the shell. `tests/test_ui_icons.py` fails when an icon the UI asks for has no rule.
- **Buttons, summaries and headings get their icon from their words** (`BUTTON_ICONS`, `SUMMARY_ICONS`, `HEADING_ICONS` in `app.js`): write a clear label and add a row to the table when a new kind of action appears. Do not hand-place icons on those.
- **Platform logos** use `platformMark(platform)` (colour from the `--plat-*` tokens, defined for both themes; X, TikTok and Threads use the ink colour). Put the logo next to the platform's name, never instead of it.
- **Long hints become an "i" by themselves** (`decorate()` in `app.js`): a `.hint` longer than ~24 characters under a `label.field`, and the grey line under a checkbox title. Mark a hint `data-keep` when people need it before choosing (a size limit); a status line (`role`/`aria-live`) never moves.
  For a label that needs its own explanation write `tip('the longer text', 'what it is about')`.
- Phones: the four navigation icons are hidden under 440 px (the labels already fill the width); everything else keeps its icon.

## New job form (2026-11-19)
Research behind it (sources: NN/g on [drop-downs](https://nngroup.com/articles/dropdown-list) and on progressive disclosure, Baymard on drop-down misuse, W3C WCAG 1.4.13 for the help popovers): hide only what people rarely need; a few choices belong side by side, not in a menu; a menu must look like a menu; help is reachable by hover, keyboard and tap and never holds the only copy of a limit; the price and the main button sit together.
- **Everything used every time is on the page**: language, clips to make, reel length (shortest to longest, one field), people in the video, brand toggles (logo, cover title, full-video banner, ending video) and "Raw recording: cut fumbles and dead air". **More options** holds only the rare ones.
- **`segmented()`** for 2 to 4 short choices (one tap, arrow keys, `role="radiogroup"`; the value lives in a hidden input with the same id). **`chip()`** for a yes/no option: icon, short name, a tick when on, the explanation behind an "i". **`fieldLabel()`**: an icon, the label and its "i". Option names are short; the long text is the "i".
- **Selects** are drawn as a control you open: raised face, chevron, pointer (`select:not(.plain)`), so they no longer look like text boxes.
- **The action bar** carries the GPU choice, the rough cost (`≈ ₹…`, the breakdown behind its "i") and Generate clips.

## Home, New job in three steps and the shared page header (2026-11-22)
Research and the clickable prototype that led to it are in the session notes (OpusClip, Klap, Vizard and Submagic keep the first screen short and let you pick what you are making; NN/g on progressive disclosure and wizards; Visa's wizard pattern).
- **Every screen starts with `pageHead(title, purpose, ...actions)`**: the title, one line of what the page is for, and the page's actions on the right (one `.btn.primary` at most). Do not write a bare `h1` any more (the job page, which shows a live title and badge, is the one exception).
- **Home (`#/`)** is where a person lands after signing in: tiles (minutes left, used, running, jobs made), "Needs you" (failed jobs, low minutes, clips ready to share, an empty brand), recent jobs, and four guides that link into the app (`#/new?goal=clean` and `#/new?goal=explainer` open New job with that goal chosen). The first-run hero replaces the tiles' emphasis until there is a job. Every item says what to do and links there; nothing on Home is only informational.
- **New job (`#/new`)** is three steps: Video, Goal, Branding. The steps are hidden panels in ONE form, so every control id and the upload code are unchanged and a step can be reached by its tab at any time. A **goal** is a card that sets the options below it (`applyGoal`): talk, vox populi (cut to speaker, 15-45 s), clean raw take (one reel), edited explainer (graphics shown whole, slow push-ins), explainer with pictures, whole video. Every goal starts from the same plain settings, so choosing another never leaves the old one's switches on. `GOALS` holds the list; add a goal there and in `applyGoal`, and in the route's `?goal=` pattern.
- **Counts and lengths are pills** (`pillGroup`, up to four short choices, one tap); "Other" opens the number fields. **Fine-tune** holds only the rare options, grouped (Selection, Cutting, Look, Sound). Brand toggles are the chips on the Branding step, with a sample clip (`.cpv`) that shows which of logo, overlay, cover title, banner and ending video are on.
- **The action bar is a summary**: a sentence of what will be made (`syncUI`), then the cost and GPU, Back, and Next (Generate on the last step). Enter in a field moves to the next step; only the last step sends. A mistake in the file or the rights box sends you back to step 1, a length mistake to step 2.
- **Brand** is split into tabs (logo and marks, cover and captions, music, defaults) with Save and the preview always in place; the tab is remembered for the session.
- Check a changed screen in dark and light at 360 px: `scripts/e2e_ui.js` follows the three steps.
